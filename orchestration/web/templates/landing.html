01The pipeline

One unit. Five agents. Each with an owner.

Every stage is a real agent built by one teammate. The unit's route decides which stages it visits.

Orchestrator routes the unit · hands each agent all the earlier evidence · checks what comes back · stores it · works out the final outcome
  1. {{ stage_card('receiving', 1, 'Every unit', 'Gemini + rules') }}
  2. {{ stage_card('prep', 2, 'FBA units', 'Gemini + rules') }} or {{ stage_card('pack', 3, 'Merchant-fulfilled (MFN)', 'Gemini + rules') }}
  3. {{ stage_card('returns', 4, 'Only if returned', 'Gemini + rules', 'is-optional') }}
  4. {{ stage_card('recovery', 5, 'Every unit · runs last', 'Rules only, no model') }}

Agents never call each other.

One orchestrator calls each agent in turn and hands it every earlier record. Routing lives in one file (orchestration/flow.json): Receiving, then Prep for FBA units or Pack for merchant-fulfilled ones, Returns only when the unit came back, and Recovery last, on everything. An agent's answer informs the workflow; only the orchestrator sets its state.

02How a decision is made

The model looks. Fixed rules decide.

The four photo agents (Receiving, Prep, Pack, Returns) use Gemini only to report what is visible. The verdict comes from code that compares that report with the order.

  1. 1 Photo

    Taken at the station with a phone or laptop camera. Each photo is stored and named by its SHA-256 hash. No photo, no verdict: the stage records no_capture.

  2. 2 The model reads

    Gemini lists what it can see: items, labels, damage, condition. Receiving, Prep and Pack never show it the order, so it cannot echo the expected answer.

  3. 3 Rules compare

    Fixed code checks that report against the purchase order, work order or customer order. Same report in, same answer out.

  4. 4 Verdict

    PassFailUncertain

    Check by check, with confidence, the model and its version, and timestamps.

UNCERTAIN never becomes PASS.

When a check cannot be decided from the photo, a person decides, and the system remembers who.

  1. UncertainThe agent says it cannot tell, and why
  2. Review queueThe workflow waits for a person
  3. OverrideA person records a verdict, with their name and a reason
  4. Nothing is erasedThe original record is kept; the stages that used it run again

Recovery is the exception: it reads no photo and calls no model. Deterministic rules check each fee line against every earlier record, and it claims money only where that evidence contradicts a charge, never on silence.

03Evidence you can trace

Follow any outcome back to the photo.

Every agent returns an evidence record. Records are written once and point at what they used.

  • Sealed with a hash

    Each record carries a SHA-256 content_hash of its own contents. Records are write-once: a second write with a different hash is refused.

  • Photos named by hash

    A record lists the exact photos it judged, by SHA-256. A photo from another unit is refused.

  • Linked to what it used

    upstream_refs names the earlier records a decision rests on, so a claim points straight at the inspections behind it.

04Built to fail safely

A broken agent never looks like a clean result.

Failures are recorded against the right stage and never turn into success. You can watch it happen live.

Switch an agent off, live

On the admin page, flip a fault switch for any agent:

  • Down does not answer
  • Timeout answers too late
  • Garbage breaks the contract
  1. Stage errorrecorded on that stage
  2. Failed / Incompletehow the workflow ends
  3. Cleannever

Switch it back on, press Resume, and the workflow finishes.

Fault-injection run

Every stage broken five ways (down, timeout, invalid output, crash, another organisation's evidence) across all {{ units }} sample units.

Another company's data stays invisible

A code for one organisation gets 404 Not found for the other's units, workflows, records and photos, exactly as if they did not exist. Every agent refuses another organisation's unit too.

05Who does what

Five people, five stations, one name on every step.

  1. Your own code

    Each teammate and judge signs in at /join with their own 8-digit access code. A code opens one organisation, or all of them.

  2. Your own station, from a phone

    Pick your agent, take the photos with the phone camera, press run. A step waits until the steps before it are done. Recovery needs no camera, just a press.

  3. Every action has a name

    Every run, photo and override records who did it. The admin reads the audit log: every sign-in, failed sign-in, change and admin action.
